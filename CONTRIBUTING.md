# Contributing

The conventions here follow [`contemno/repo_standard`](https://github.com/contemno/repo_standard);
the rationale for each rule is in its `STANDARD.md`.

## Branching & promotion

Promotion flow: **`feature branch → dev → main`**.

- Branch from `dev`; name `<topic>` (or `claude/<topic>` for agent work).
- **Open every PR against `dev`.** `main` is release-only; `dev → main` is the
  release promotion step.
- Releases are auto-tagged (`.github/workflows/autotag.yml`). The version is
  `max(patch-bump, ./VERSION)`. Patch releases are automatic — to cut a
  **minor/major**, bump `VERSION` in the `dev` PR.
- **`dev → main` promotion PRs merge with "Create a merge commit" — never rebase
  or squash.** Doing either rewrites the promoted commits so `main` stops being a
  descendant of `dev`, and the next promotion then conflicts on every file both
  sides touched. See `repo_standard`'s `STANDARD.md` → *Process* for the recovery
  recipe if this already happened.

## Work loop

1. Pick or open an issue (use the forms in `.github/ISSUE_TEMPLATE/`).
2. Branch from `dev`.
3. Open a PR with **base `dev`**, body containing `Closes #<issue>`.
4. On merge, the issue closes and the release pipeline runs on `dev`.

## Local checks

- `make lint` — rustfmt + clippy (`-D warnings`) + Python/shell syntax. This is
  exactly what CI's `rust` and `scripts` checks run; the checked-file lists live
  only in the `Makefile`, so extend them there, not in workflow YAML.
- `make test` — the full workspace test suite. The policy crates
  (`balancer.rs`, `wake_graph.rs`, `config.rs`, `scx_cohort_common`) are
  unit-tested without a kernel; no root or sched_ext support needed.
- Run `./scripts/install-hooks.sh` once to install the fast pre-push hook
  (`make lint-fast`: rustfmt + script syntax, seconds — clippy is deliberately
  excluded because it needs a full BPF/libbpf build).

Building (and therefore clippy/test) needs the toolchain from
[`README.md`](README.md) → *Requirements*: clang ≥ 16, rustc ≥ 1.82,
`libelf-dev`, `zlib1g-dev`.

## Before a PR is ready (and after each conflict resolution)

A clean diff against a *stale* base hides regressions. Before marking ready — and
again after resolving any conflict:

1. **Re-sync with base.** `git fetch origin dev` and rebase.
2. **Check what else touched your files:**
   `git log --oneline <branch-point>..origin/dev -- <file>`. If another PR changed
   it, read the **current `dev` version** of the functions you're editing and
   reconcile *intent* — don't just re-apply your hunks.
3. **Treat the conflict resolution as authored code** — pin each side's intent
   with a test.
4. **Confirm the gates are green** locally and that the PR's required checks
   actually reported (a required check that never ran is not a pass).
5. **Move the docs** (see below).

## Done = docs updated

Every change moves its matching artifact — `README.md`, `DESIGN.md`,
`bench/README.md`, `--help` text, or the layout tests in `scx_cohort_common` —
or explicitly notes N/A. The PR template has a checkbox for this — keep it
honest.

## Project invariants

The PR and issue templates pin three guarantees; changes that touch them need
both sides to move together:

- **Rust is the single source of truth for the BPF↔userspace ABI.** Shared
  structs/constants live only in `scx_cohort_common`; `scx_cohort/src/bpf/intf.h`
  is generated by cbindgen at build time and never hand-edited; the layout tests
  move with any struct change.
- **The BPF per-wakeup hot path makes decisions from map lookups only.**
  Heavy policy belongs in the daemon's tick, not the wakeup path.
- **The scheduler is always safely detachable.** Daemon exit, Ctrl-C, panic, or
  the sched_ext watchdog must fall back cleanly to EEVDF.

## Security

Never report vulnerabilities as public issues — see [`SECURITY.md`](SECURITY.md).
